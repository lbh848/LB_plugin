# LightBoard illustration status plugin

RisuAI의 생성 이벤트를 감지해 삽화 서버 진행 상태를 표시하는 보조 플러그인입니다. 메시지·채팅 인덱스·이미지는 플러그인이 읽거나 전송하지 않으며, 이미지 생성 자체는 모듈이 담당합니다.

배포 파일은 `lightboard_illust_status.js` 하나입니다. 파일명과 GitHub 경로는 앞으로 고정하고, 릴리스마다 `//@version`만 증가시킵니다.

백엔드 소스와 실행 환경은 이 저장소에 포함하지 않습니다. 백엔드 작업 위치는 로컬 작업 지침인 `AGENTS.md`와 `CLAUDE.md`를 따릅니다.

## 최초 GitHub 설정

1. 공개 저장소 `lbh848/LB_plugin`과 기본 브랜치 `main`을 유지합니다.
2. 이 폴더를 저장소에 push합니다.
3. 다음 raw URL을 브라우저에서 열어 JS 원문이 표시되는지 확인합니다.

   `https://raw.githubusercontent.com/lbh848/LB_plugin/main/lightboard_illust_status.js`

4. RisuAI 플러그인 설정의 맨 위 `+` 버튼으로 이 JS 파일을 한 번 직접 설치합니다.

현재 기존 설치본에는 `update-url`이 없으므로 이 최초 1회 수동 설치가 필요합니다. 같은 내부 이름의 플러그인이 있다는 확인창이 뜨면 업데이트를 승인합니다. 그 뒤부터 원격 파일의 버전이 설치본보다 높으면 설치된 플러그인 항목 옆에 녹색 `+` 업데이트 버튼이 나타납니다.

Risu의 맨 위 `+`는 파일 가져오기 버튼이고, 설치된 플러그인 오른쪽의 녹색 `+`가 온라인 업데이트 버튼입니다. 둘은 다른 버튼입니다.

## 일반 사용

1. 플러그인의 `soya comfy 플러그인`을 누릅니다.
2. HTTPS 서버 주소를 입력하고 `Save & check`를 누릅니다.
3. `백엔드 활성 봇`에서 현재 서버 봇을 확인하고 선택할 수 있습니다.
4. 모듈의 `작동 모드`에서 `자동` 또는 `수동`을 선택합니다. 수동은 답장 직후 생성하지 않고 답장에 `삽화` 버튼만 표시합니다.
5. 수동 모드에서는 답장의 `삽화` → `삽화 생성 / 다시 만들기`를 눌러 그 답장의 생성을 시작합니다.
6. generation, CALL1부터 시작하는 전체 재생성, raw 전체 생성, 이미지별 raw 재생성·편하게 수정 때 진행창이 표시됩니다.
7. 정적 이미지 호버에는 `✎ 편하게 수정`이 표시되고, 애니메이션 이미지에는 `↻`과 `×`만 표시됩니다. 애니메이션 슬롯의 편집 동작 코드를 직접 호출해도 모듈과 백엔드가 모두 거절합니다.
8. 진행창 표시를 꺼도 생성 연동과 필요한 동안의 상태 확인은 계속 작동합니다.

서버 주소를 저장하기 전에는 요청하지 않으며, 평소에는 폴링하지 않습니다. 생성 신호가 있거나 대시보드를 열어 직접 확인할 때만 서버 상태를 조회합니다. 작업이 완료되거나 오류·취소 상태로 종료되면 플로팅 진행창은 자동으로 닫힙니다.

호환 구성은 soya-v49 모듈과 illustration context bridge version 8 서버입니다. 키비주얼과 일반 장면 모두 슬롯별 서버 이미지 URL을 위에 표시하면서 같은 결과의 Risu 로컬 PNG 인레이를 fallback으로 보존합니다. 서버가 PNG를 보내면 정지 이미지가, GIF 또는 올바른 MIME의 animated AVIF/WebP를 보내면 애니메이션이 표시됩니다. 서버 세션이나 임시 HTTPS 주소가 사라지거나 클라이언트가 포맷을 디코딩하지 못하면 로컬 첫 프레임이 남습니다. v49는 기존 단축 슬롯 매니페스트의 opt-in 확장으로 애니메이션 슬롯 번호를 함께 받아 해당 슬롯에서만 `편하게 수정`을 숨깁니다. v48 이하에서 이미 저장된 채팅 항목에는 이 구분 속성이 없으므로 애니메이션에도 버튼이 남을 수 있으며, 해당 항목을 `↻`로 한 번 갱신하면 v49 구분이 적용됩니다. 일반 생성과 전체·그림별 재생성 및 정적 이미지 편하게 수정은 시작 전에 서버 연결을 최대 5초만 확인하고, 연결되지 않으면 생성 요청 없이 즉시 오류로 종료합니다.

## 업데이트 배포

코드를 수정한 뒤 `//@version`을 반드시 이전 공개 버전보다 높이고 `./verify.ps1`을 실행한 다음 commit/push합니다. GitHub raw 캐시가 갱신된 뒤 RisuAI에서 업데이트 확인을 하면 녹색 `+`가 나타납니다.

Risu의 플러그인 교체 과정은 헤더 `//@arg` 사용자 값을 기본값으로 다시 만들 수 있습니다. 서버 주소는 플러그인 저장소와 캐릭터 변수에도 저장되므로 유지되지만, 폴링 간격 등을 직접 바꿨다면 업데이트 후 다시 확인하십시오.

자세한 불변 조건과 과거 문제는 [DEVELOPMENT.md](DEVELOPMENT.md), 배포 순서는 [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md)를 참고하십시오.
